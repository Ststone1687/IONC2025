教室燈光依舊明亮，螢幕中央浮現幾個大字：「動態規劃」。你靜靜坐在座位上，翻開筆記。前排的朋友早已拿出自製筆記本，神情興奮。
講師走到講台，打開投影片。
講師：「大家早，今天我們要學的是——動態規劃。」
講師停頓片刻，目光掃過全場，嘴角微微上揚。
講師：「這是最容易讓人愛上，也最容易讓人懷疑人生的單元之一。」
教室裡響起一陣低低的笑聲。朋友小聲湊過來。
朋友：「欸欸，我昨天才剛學完背包，今天就要打 BOSS 了嗎？」
你淡淡看了他一眼，沒說話。
（動態規劃……是該打起精神了。）
講師轉身操作投影，打開第一張投影片。
講師：「我們從簡單的子序列問題開始——Longest Increasing Subsequence。」
隨著解說展開，投影片逐漸被 dp[i]、轉移式和邊界條件填滿。你一邊記錄，一邊思考規律。
講師邊寫邊說。
講師：「注意，這裡我們要找的是最長嚴格遞增子序列，也就是說——不能有相等的元素。」
講師：「想一下，如果我們的 dp[i] 表示以第 i 個元素結尾的 LIS 長度，那就可以從所有前面的 j 進行轉移，只要 a[j] < a[i]，就有 dp[i] = max(dp[i], dp[j] + 1)。」
朋友一臉迷惘地抓抓頭。
朋友：「等等，我覺得我腦袋開始轉不過來了……怎麼又是從 j 跑到 i？我以為動態規劃都要順著跑？」
你翻了一頁筆記，頭也不抬地回答。
主角：「這就是順著跑，只是每個狀態都要考慮前面所有可能的轉移來源。」
朋友：「哦哦……所以等於是每個點都在問：『以我結尾的最佳結果是什麼』，然後從前面的最佳結果中選？」
你微微點頭。
主角：「理解起來不難，實作起來也還行，但優化成 n log n 就要用貪心加二分。」
朋友一臉驚恐。
朋友：「還要貪心？還要二分？這還叫基本款？！」
你沒回話，繼續抄下優化寫法的草圖，心裡默默預期這節課會越來越硬。
講師聽到後排的困惑笑聲，微微一笑。
講師：「放心，這只是開胃菜。接下來我們來看 Longest Common Subsequence，也就是經典的『兩字串最長公共子序列』問題。」
講師在投影片上寫下兩個字串：a b c d e f 與 b d e g。
講師：「請問，這兩個字串的 LCS 是什麼？」
幾位同學低聲討論。朋友轉頭看你。
朋友：「你要不要猜猜看？」
主角：「b d e。」
朋友：「欸？你不算一下嗎？」
主角：「不用。」
朋友無語地眨眨眼。
朋友：「你是不是其實是 AI 轉生的？」
你沒理會，只是淡淡地繼續寫下轉移式：
主角：（dp[i][j] = dp[i-1][j-1] + 1 if a[i] == b[j] else max(dp[i-1][j], dp[i][j-1])）
筆劃清晰，節奏穩定，就像這些公式早已在腦中演練過無數次。
螢幕換成新投影片，標題寫著：「0-1 背包問題」。
講師語氣變得沉穩。
講師：「現在要進入一個大家都逃不掉的單元了……背包。」
台下立刻響起幾聲哀嚎，有人誇張地仰頭，有人用筆敲桌。
朋友雙手一攤，整個人癱在椅背上。
朋友：「啊啊啊，背包……我最不會的來了。」
你瞥他一眼。
主角：「你昨天才說這題你看過。」
朋友：「看過跟會做完全兩回事啦！」
你沒再說什麼，開始翻回前幾頁筆記。講師已經在投影片上秀出定義。
講師：「給定 n 個物品，每個物品有重量 w[i] 與價值 v[i]，背包總容量為 W，問怎麼裝才能讓總價值最大？」
講師：「狀態定義：dp[i][j] 表示前 i 個物品，背包容量為 j 的最大總價值。」
講師：「如果你寫成一維也沒錯，這叫做滾動陣列優化。」
你熟練地一邊寫一邊默背。
主角：「dp[i][j] = max(dp[i-1][j], dp[i-1][j-w[i]] + v[i])，前者是不裝，後者是裝。」
朋友瞪大眼看你寫筆記的速度。
朋友：「你是不是根本不用聽？直接可以教我們了吧……」
你沒回應，只是寫完最後一筆轉移後補了一句：
主角：「這種東西光看公式沒用，得自己寫幾遍。」
朋友：「啊，好有道理但我又好想哭。」
講師帶著大家做幾題練習，像是「有三個物品，容量為七，最大總價值為？」這類題目。
你三兩下就寫完，朋友還在紙上畫小格子。
你轉頭拉了拉他的筆記本，把格式排整齊。
主角：「你這樣 dp 表不好讀。」
朋友：「欸？你會幫我排……嗚，我好感動。」
你把筆推回他手裡。
主角：「只是順眼一點。」
朋友：「冷漠……但有效……愛了。」
講師切換投影片。
講師：「接下來進入『區間 DP』。這是個沒明顯遞推方向的經典題型，一開始會讓人很迷，但掌握模式後會覺得它漂亮極了。」
教室安靜了幾秒。
講師：「舉例：括號配對、取石頭問題。」
他畫出一條序列，標上左右區間。
講師：「核心思路是：要合併整段區間，就要找一個分點，把它拆成左右兩段去解，然後合併。」
你下意識打開電腦，搜尋經典題複習。朋友湊過來看。
朋友：「這個我真的不熟，合併成本是什麼意思啊？」
你畫了兩段序列，劃出分點，邊寫邊說：
主角：「這裡是 dp[i][j]，你要試所有 k 在中間，看 dp[i][k] + dp[k+1][j] + 合併代價 哪個最小。」
朋友眼神逐漸明亮。
朋友：「喔喔！原來就是試所有切法的意思？哇靠，原來這就是動規的『枚舉分點』！」
你點頭。
主角：「區間 DP 難在代價怎麼合，有時是前綴和，有時是最小值。」
講師往下帶，進入新單元：
講師：「接著是位元 DP。」
他頓了一下。
你立刻坐直。
（來了，這是很多人沒聽過但一旦接觸就覺得神奇的東西。）
朋友露出迷茫表情。
朋友：「這個……我昨天查了一下，感覺好像是……用來數數字的？」
你輕聲補充：
主角：「其實就是用位元狀態表達東西選不選。」
朋友：「蛤？這樣也行喔？」
主角：「能，而且很經典。」
朋友：「天啊，這個比背包還爆炸……我覺得我今天大腦快報廢了。」
你沒說話，講師換新投影片。
講師：「旅行推銷員問題：TSP（Traveling Salesman Problem）」
投影片上幾個節點圍成不規則多邊形，每個點間標註距離。
講師：「假設你是一名業務員，要拜訪每個城市一次，最後回到原點，問最短路徑是多少？」
朋友一臉驚恐。
朋友：「不會吧，這種題目居然也算 DP？」
你淡淡回答：
主角：「可以用位元表示走過哪些城市，轉移狀態是 dp[mask][i]。」
朋友眼神發直。
朋友：「那個 mask 是……？」
你拿過他的筆記本，畫出二進位狀態。
主角：「假設有 4 個城市，mask 是 1011，代表你走過第 0、1、3 號城市，i 表示現在在哪。」
主角：「轉移時試著從走過的城市中，往還沒去過的轉移，再更新最小距離。」
講師同步在螢幕上寫下公式：
主角：（dp[mask][i] = min(dp[mask ^ (1 << i)][j] + dist[j][i])）
講師：「這是經典的位元 DP，時間複雜度 O(n² * 2ⁿ)，通常能解到 n = 16。」
你點點頭，腦中浮現練習題。朋友則躲在筆記後喃喃自語。
朋友：「啊啊啊，bit 操作……我回去一定要惡補這一塊……」
講師露出淡淡微笑，切換到最後一張簡報。
講師：「今天壓軸，是冷門但有趣的單元——SOS DP。」
教室陷入短暫沉默。
你也愣了一下。這題目平常不太會在營隊課程出現。
講師繼續解釋：
講師：「Subset Optimization over Subsets，簡稱 SOS。這是一種針對所有子集合進行快速轉移的技巧，常用於狀態壓縮問題。」
講師：「本來你要窮舉所有子集合，但 SOS 可壓成 O(n * 2ⁿ) 用 bit 動態轉移完成。」
講師：「這樣就能快速統計所有子集合的和，或計算包含某些條件的總數。」
朋友癱軟在桌。
朋友：「啊啊啊……這課程太殘忍了……」
你合上講義，長出一口氣。講師宣布下課。
你抬頭，看見門口聚著幾個人影，有的還在討論課堂內容，有的已經在聊午餐選項。
陽光透過百葉窗，落在講桌上，投下整排光影。心裡還殘留著未平的餘韻。
（Digit DP、TSP、SOS……不管哪一個，其實都還有很多變形可以深入。今天的課，還不錯。）
朋友一邊收東西，一邊碎碎念。
朋友：「我等一下便當要選燒雞……欸你咧？」
你沒馬上回答，只把筆電收好，輕聲回道：
主角：「還沒決定。」
朋友挑挑眉。
朋友：「連便當也這麼謹慎，你真的很理性欸……我決定了，你的新外號就叫『小冷哥』了。」
你皺了下眉。
主角：「別亂取。」
朋友：「嘿嘿，至少不是『冷漠男』吧？」
你不再理會他，站起身，看向走廊方向。
